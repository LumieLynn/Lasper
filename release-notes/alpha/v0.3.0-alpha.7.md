# Lasper v0.3.0-alpha.7

This pre-release completes the current backend and daemon decomposition, improves TUI input and terminal reliability, and consolidates the lifecycle, provisioning, and host-integration paths introduced during the alpha.6 development cycle.

## Backend architecture

- Establish explicit domain, application, adapter, composition, daemon, and TUI ownership boundaries while retaining the transitional nspawn models for compatibility.
- Move runtime observation, machine and image lifecycle services, provisioning composition, session handling, and host integrations behind typed interfaces.
- Add architecture boundary tests that prevent outer-layer imports, transport types, and process authority from leaking into domain or application code.
- Split the daemon into protocol, dispatch, job, session, server, and logging responsibilities, and remove the obsolete duplicate `dbus_system_operation` route in favor of typed operation families.

## Daemon and operation handling

- Make daemon query, command, job, and session routes explicit so resource claims and long-running operation ownership are visible at the dispatch boundary.
- Keep deployment jobs durable across client-side timing changes, reconcile unknown outcomes against host state, and preserve unresolved work for explicit recovery decisions.
- Keep the elevated control surface typed and bounded while retaining the existing authenticated session and root-daemon lifetime model.

## Provisioning and lifecycle

- Centralize image and machine lifecycle behavior so start, removal, inspection, and transitional states share the same service contracts.
- Improve deployment preparation and rollback composition for bootstrap, clone, OCI, storage, systemd configuration, NVIDIA state, unit drop-ins, and Wayland grants.
- Preserve ownership evidence and ambiguous artifacts during recovery instead of deleting resources that cannot be attributed to the current deployment.
- Keep guest DNS defaults aligned with systemd-nspawn network semantics and restrict port forwarding to supported Veth and bridge modes.

## TUI and terminal

- Move terminal ownership and application event coordination under `tui`, isolate keyboard and mouse input handling, and prevent pointer bursts or stale input from starving the event loop.
- Bound terminal and journal queues, preserve PTY writer errors, coalesce redraw work, and retain the relevant dekit terminal fixes for narrow layouts and arbitrary byte streams.
- Keep modal focus, deployment cancellation confirmation, inspector selection, image start transitions, and terminal fallback behavior explicit in the UI state machine.
- Improve the wizard's host-integration controls for per-user Wayland grants, NVIDIA device selection, package inheritance, network mode semantics, and unsupported-option feedback.

## Compatibility and caveats

- OCI application images remain experimental and require systemd 260 or newer with `importctl pull-oci`; they are not automatically bootable system-container root filesystems.
- Native bootstrap and Tar/Raw workflows remain available on supported older systemd hosts, with GNU tar 1.35 or newer recommended for untrusted archives.
- The elevated daemon, OCI provider, private-user allocation, GPU and display passthrough, and namespace terminal fallback still require careful review of [CAVEATS.md](../CAVEATS.md) and [SECURITY.md](../SECURITY.md).
