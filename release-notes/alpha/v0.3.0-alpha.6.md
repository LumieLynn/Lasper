# Lasper v0.3.0-alpha.6

This pre-release hardens the systemd-native OCI workflow introduced in alpha.5, makes deployment cancellation and rollback materially more reliable, closes the elevated daemon's proc-reopenable RPC channel, and adds explicit resource bounds around image imports, terminal I/O, and privileged session diagnostics.

## Elevated daemon boundary

- Move the main privileged JSON-RPC channel from child stdin/stdout pipes to a private per-session Unix socket, preventing another same-UID process from reopening a TUI pipe through `/proc/<pid>/fd` and injecting root operations.
- Require the daemon to authenticate the launching TUI's exact PID and UID with kernel `SO_PEERCRED`, require the TUI to verify that its control peer is root, and negotiate the random FD token only after the control peer is accepted.
- Reject non-root daemon execution, unknown RPC fields, malformed bootstrap state, oversized protocol frames, slow FD handshakes, and excess concurrent FD setup connections.
- Pin and monitor the launching TUI with a Linux pidfd so a daemon waiting for its initial connection cannot remain indefinitely after its owner exits.
- Terminate tracked command and terminal process groups during daemon shutdown, request cancellation for active OCI transfers, and install a kernel parent-death signal on direct command children as a final orphaning guard.
- Rate-limit rejected-connection diagnostics so a local connection flood cannot grow the privileged log without bound.
- Write each daemon session to a uniquely named, root-owned `0600` log under `/var/lib/lasper/logs`, cap each file at 8 MiB, and retain up to eight unlocked sessions within a 64 MiB directory budget without deleting logs held by active daemons.

## OCI runtime and PrivateUsers

- Promote systemd's complete image-adjacent OCI `.nspawn` configuration into `/etc/systemd/nspawn/`, preserve generated execution fields, mark the promoted copy as Lasper-owned, and refuse to replace unrelated administrator configuration.
- Use a system-scoped OCI import with `PrivateUsers=no` for newly pulled root-owned mstack images; this keeps their layers writable instead of applying `managed` to ownership that was not prepared in systemd's foreign UID/GID range.
- Validate externally prepared `PrivateUsers=managed` configurations against the effective private-network requirement and leave the final systemd compatibility decision visible instead of pretending that managed allocation repairs incompatible layer ownership.
- Preserve `Boot=`, `Parameters=`, `User=`, `Environment=`, and `WorkingDirectory=` when promoting OCI configuration, and allow systemd to decide whether an externally prepared payload can boot rather than rejecting `Boot=yes` in Lasper.
- Add a typed namespace terminal fallback for running containers without a usable system bus, selecting the leader from machined's validated runtime registration and attaching through a fixed `nsenter` namespace set with `/bin/bash` or `/bin/sh`.
- Distinguish shared and private user namespaces when building the fallback command so `PrivateUsers=no` containers do not receive the invalid user-namespace reassociation used by managed containers.
- Keep namespace attachment restricted to root or the authenticated elevated daemon because it opens a container root shell without using the container login service.

## Resolver and network policy

- Stop mutating `/etc/resolv.conf` during rootfs provisioning and delegate resolver behavior to systemd-nspawn's `ResolvConf=` setting.
- Write explicit Host, Isolated, and Veth policies using systemd's `Private=`, `VirtualEthernet=`, and `ResolvConf=` semantics so the service template cannot silently supply a conflicting network mode.
- Validate port forwards, interface names, optional hostnames, OCI registry hosts, and registry ports against the grammar accepted by their systemd or OCI consumers.
- Accept OCI references that contain a registry port without confusing that port with an image tag.

## Deployment cancellation and rollback

- Add a visible deployment cancellation command and confirmation dialog, and prevent confirmation input from leaking into the deployment view or triggering cancellation accidentally.
- Keep active host mutations and terminal sessions in the quit warning so the application does not present shutdown as harmless while privileged work is still running.
- Make bootstrap, image clone, and OCI pull cancellation wait for confirmed process or transfer outcomes instead of reporting success immediately after dropping a local client future.
- Cancel the authoritative systemd-importd transfer for interrupted OCI pulls and let a racing authoritative completion win over a late cancellation request.
- Model clone sources as persistent images rather than requiring a running machine, while retaining image-name semantics distinct from stricter nspawn machine names.
- Record which storage, configuration, NVIDIA state, and unit artifacts were created by the current deployment so rollback removes only owned resources and leaves ambiguous or pre-existing state untouched.
- Stop storage rollback when a raw image cannot be unmounted cleanly, preserving its loop devices and backing state for diagnosis instead of continuing into unsafe deletion.
- Split systemd image removal from optional Lasper artifact cleanup; preserve unknown unit drop-ins and remove the drop-in directory only when Lasper's known files leave it empty.

## Image import and host mutation safety

- Apply the managed image-size limit to local files, downloads, decompression output, raw imports, and bounded copies from non-regular sources.
- Preflight Tar archives with entry-count, metadata-byte, and declared-expansion limits, including PAX and GNU sparse size records, before extraction begins.
- Apply a child file-size limit during extraction and bound captured Tar diagnostics so malicious input cannot consume unbounded disk space or daemon memory through one file or one error stream.
- Probe the effective privileged Tar runtime before remote deployment; protected runtimes continue directly, while old or unrecognized implementations require an explicit confirmation bound to the current URL and typed request.
- Keep local Tar archives warning-only for distribution compatibility, ignore `TAR_OPTIONS`, and document GNU tar 1.35+ as the recommended runtime for untrusted archives.
- Validate sudoers installation against the host include policy and effective `visudo` configuration, and fail instead of writing a fragment when neither the `sudo` nor `wheel` group can be assigned.

## Terminal, image, and hardware reliability

- Port the relevant dekit terminal fixes for narrow grids, scrolling, unterminated control strings, and arbitrary byte streams while preserving the upstream MIT notice.
- Route terminal-generated VT replies through the sole PTY writer, bound terminal input and journal queues, coalesce redraw work, and surface full or closed channels instead of silently losing input.
- Restore the host terminal after initialization failures and fall back from unusable runtime directories only to a private user-owned location.
- Correct the systemd `EnableUnitFiles` D-Bus signature and inspect image units directly through `systemctl` without requiring a running machined registration.
- Parse structured machinectl, NVIDIA CDI, and loop-device data where the tools provide it; derive the selected CDI devices and mounts from one generated snapshot so discovery cannot mix different hardware states.
- Fail closed on malformed or unusable NVIDIA CDI output, preserve CDI read/write mount semantics, and remove only bindings whose source, destination, and access mode match Lasper's recorded ownership.
- Escape colons and backslashes in nspawn bind paths, reject destination conflicts before rootfs mutation, and skip optional X11 directory binds when the source is not a real directory.

## Compatibility and remaining caveats

- OCI application import still requires systemd 260 or newer with `importctl pull-oci`; OCI publisher signatures are not verified, so trusted registries and immutable digests remain important.
- A Lasper-imported root-owned mstack is intentionally configured with `PrivateUsers=no`, which disables user-namespace isolation; changing it to `managed` does not remap its layers and can make the payload appear as `nobody` or remain read-only.
- Externally prepared managed mstack images require foreign-owned layers, private networking, working `systemd-nsresourced` and `systemd-mountfsd`, and host support for the systemd managed-allocation path.
- The nsenter terminal fallback provides namespace entry only; it cannot add an init system, repair ownership, make a read-only mstack writable, configure an address, or make an arbitrary OCI image bootable.
- Daemon session logs are diagnostic records rather than tamper-evident audit storage, and the elevated daemon still carries the typed host authority needed to manage containers.
- Alpha.6 remains pre-release software. Backend decomposition, durable long-operation reporting, and broader host smoke coverage remain part of the bar for `v0.3.0` stable.
