# Lasper v0.3.0-alpha.5

This pre-release introduces Lasper's systemd-native OCI application-image workflow, completes the current typed privilege-boundary migration, separates runtime observation from machine control, and substantially revises the Machines, Images, Inspector, and integrated-terminal experience.

## OCI application images

- Add an experimental OCI provider backed by systemd 260+'s typed `importctl pull-oci` operation instead of extracting Docker or Podman images as conventional root filesystems.
- Accept validated OCI distribution references and install the result as a systemd-managed `.mstack` image under `/var/lib/machines` in both direct and elevated execution modes.
- Present OCI as an application-image workflow in the creation wizard, including its systemd-owned storage model and the fact that arbitrary OCI images are not assumed to be bootable system containers.
- Keep OCI runtime configuration with the imported application image rather than generating a conventional `.nspawn` root-filesystem configuration for it.
- Expose regular images separately from dot-prefixed internal images such as OCI dependency layers, while retaining systemd's own visibility and removal semantics.
- Protect host, temporary, and active machine resources during image removal, and route hidden-image removal through systemd's image-management path instead of treating hidden names as invalid machines.

## Runtime and backend architecture

- Introduce explicit `RuntimeSource` and `MachineControl` ports so read-only observation no longer shares the same abstraction as lifecycle mutations.
- Normalize machines and images into one ordered `RuntimeSnapshot`, preserving stable selections and updating the UI from a coherent backend result.
- Observe active machines from systemd runtime registrations and obtain images through non-interactive systemd queries, avoiding repeated per-view discovery and authentication-prone `machinectl list` calls.
- Combine D-Bus event nudges, filesystem observation, and a bounded CLI heartbeat so runtime changes are refreshed without depending on one notification source.
- Centralize machine inspection and fallback behavior across D-Bus, CLI, direct, elevated, and CLI-only modes.
- Keep CLI-only execution free of daemon-side zbus initialization while routing elevated CLI inspection through a typed, fixed `machinectl` and `systemctl` request.
- Retain the legacy container backend only as a compatibility adapter while concrete runtime and control implementations use the new split interfaces.

## Typed privilege boundary

- Remove the remaining normal elevated paths for arbitrary `program + argv`, unrestricted absolute-path file operations, and generic streaming commands.
- Route machine lifecycle, image removal and cloning, storage, `.nspawn` configuration, systemd drop-ins, inspection, terminal setup, bootstrap, Tar/Raw import, and OCI acquisition through typed requests.
- Use fixed executables, validated request models, daemon-derived managed paths, explicit option separators, and structured operation results in both direct and elevated modes.
- Pass local and downloaded Tar/Raw image sources into the elevated daemon by file descriptor, keeping caller-controlled source paths and credentials out of the privileged request.
- Validate imported Raw images with `systemd-dissect` and keep typed storage conflict checks around directory, subvolume, and disk-image publication.
- Tighten machine names to systemd-compatible hostname labels, rejecting underscores, option-shaped labels, empty labels, label-edge hyphens, traversal, and control characters before command construction.
- Preserve the broader filename grammar required for systemd image names instead of incorrectly applying machine-name validation to internal and application images.

## Lifecycle safety and recovery

- Make external deployment rollback ownership-aware: systemd-managed storage is removed only after the provider returns an explicit ownership receipt.
- Leave ambiguous external storage untouched when provisioning fails before ownership is established, preventing cleanup from deleting a pre-existing image.
- Keep Lasper-managed local storage cleanup separate from externally managed image cleanup so rollback cannot fall through to the wrong backend.
- Add explicit start observation and service-failure reporting instead of treating command dispatch alone as a completed machine start.
- Show a synthetic `Starting` machine immediately when an image is started, reconcile it when systemd-machined publishes the runtime registration, and remove it on failure or timeout.
- Prevent repeated starts and terminal attachment while a machine is still starting or exiting.

## Machines, Images, and Inspector

- Replace the previous stopped-container approximation with separate Machines and Images resource lists: Machines represent runtime registrations, while Images represent persistent systemd-managed resources.
- Add Regular and Internal image views with independent selection, stable sorting, image-aware actions, and clear empty states.
- Replace the old Image Information panel with a resource-aware Inspector that follows the originating Machines or Images list.
- Let regular powered-off images expose Overview, Config, and Unit panes, including discovered `.nspawn` source paths, static machine properties, unit identity, and systemd drop-ins without requiring the machine to be running.
- Limit internal images to the information that systemd actually exposes and label `.mstack` resources as OCI application images with systemd-owned storage.
- Allow a regular image to open the terminal session of its exact same-name running machine, while rejecting internal, stopped, starting, and exiting resources with an explicit status.
- Pair each list with its own stop in the logical focus order: Machines, Machine Inspector, Images, Image Inspector, Terminal; `Shift+Tab` is the exact inverse and maximized terminal mode skips hidden inspectors.
- Retain the Inspector's selected resource while it owns focus, so entering a machine Inspector cannot accidentally switch it to the currently selected image.

## Terminal and TUI interaction

- Give the integrated terminal a taller default split and restore the latest non-terminal focus when the active terminal session closes or is hidden.
- Coalesce high-frequency PTY redraw notifications and bound event draining per frame so terminal output cannot starve rendering, keyboard input, or shutdown handling.
- Retry PTY resize delivery when the writer queue is full, surface writer and ioctl failures, and keep the parser dimensions synchronized with the requested pane size.
- Honor application-cursor mode, hidden-cursor state, terminal mouse tracking modes, and legacy byte, UTF-8, and SGR mouse encodings.
- Add terminal encodings for common navigation keys, function keys, modifier combinations, and `BackTab` while avoiding invalid byte sequences for unsupported input.
- Restrict terminal mouse events to the terminal content area while preserving explicit drag capture when a selection or terminal mouse gesture leaves the pane.
- Give active dialogs, confirmations, help, power menus, and wizard overlays modal ownership of keyboard and mouse input so events cannot leak into background panels or an insert-mode terminal.
- Add wheel scrolling and corrected viewport-aware scrollbar state to Inspector panes, the passthrough wizard, and NVIDIA configuration dialogs.

## Compatibility and remaining caveats

- OCI application import requires systemd 260 or newer with `importctl pull-oci`; native bootstrap and Tar/Raw image workflows remain available on supported older systemd hosts.
- Registry transport is authenticated with HTTPS, but Lasper does not verify OCI publisher signatures yet; use trusted registries and immutable digests when provenance matters.
- An OCI application image may not contain `systemd`, a system bus, login support, or a bootable init process, so importing it does not make it equivalent to a native system-container image.
- The elevated daemon now exposes typed product operations rather than generic command and file RPCs, but it still carries the host authority required to manage containers and is not a trust boundary against code already executing inside the Lasper process.
- Alpha5 remains pre-release software for testing and personal workflows; review [CAVEATS.md](../CAVEATS.md) and [SECURITY.md](../SECURITY.md) before using it on a system with important host resources.
