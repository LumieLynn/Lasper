# Lasper v0.3.0-alpha.2

This pre-release is a focused hotfix for elevated daemon startup in
`v0.3.0-alpha.1`.

## Fixed

- Create the private elevated-daemon socket directory with an explicit `0700`
  mode. `tempfile` otherwise creates directories from `0777 & !umask`, which
  caused Lasper's strict post-creation security check to reject the directory
  under common umasks such as `0002` and `0022`.
- Preserve the strict ownership and mode verification after directory creation.
  The fix does not relax the elevated daemon's security boundary.
- Close the daemon bootstrap stdin pipe before waiting for the child process,
  preventing a failed or abandoned startup from leaving the root daemon waiting
  indefinitely for input.
- Report whether elevated daemon startup failed while launching `sudo`, during
  the daemon health check, or while preparing a protected path instead of
  always presenting a generic sudo-permission hint.

## Validation

- Verified `lasper -e` startup as a normal user with `umask=0002`.
- Added a regression test that asserts the socket directory is owned by the
  invoking user and has mode `0700`.
- Passed the complete test suite, strict Clippy checks, rustfmt, and release
  build locally.

Users of `v0.3.0-alpha.1` who rely on `lasper -e` should upgrade to this
pre-release.
