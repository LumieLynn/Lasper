# Lasper v0.3.1

Lasper 0.3.1 adds Wayland-aware container shells, a command launcher for desktop entries, and a built-in selected-user prompt in the TUI. It also improves terminal responsiveness, reduces runtime memory overhead, and fixes deployment and systemd-tools lifecycle handling.

## Shells and desktop integration

- Enter a container with `lasper shell user@machine`, or append an absolute guest executable and its arguments, with an optional `--` separator.
- Use `lasper launch user@machine -- /usr/bin/kitty` in a `Terminal=false` desktop entry. Launch uses the caller's authority and the host's systemd/polkit authentication; interactive shells can also use the elevated daemon.
- Automatically validate Wayland access when the current host display socket is declared in the container's startup binds. Accept custom guest destinations, source aliases, and multiple candidate binds while checking guest identity, permissions, and socket identity.
- Select a specific socket with `--wayland=DISPLAY`, or skip display setup with `--no-wayland`. Automatic interactive-shell validation can fall back to a terminal-only shell with one concise notice; explicitly selected displays remain strict.
- Forward `TERM`, `COLORTERM`, and `NO_COLOR`. Press `Ctrl+]` three times within one second to detach; `lasper shell --quiet` suppresses detach and successful Wayland fallback notices.
- Fix probe parsing around terminal control sequences, PTY input forwarding, getty restarts, D-Bus terminal latency, and slow attachment teardown. Bound output draining after a reported exit so inherited PTY descriptors cannot keep `shell` or `launch` waiting indefinitely.

## TUI terminals

- Make `t` open Lasper's username prompt; exiting a guest shell returns to that prompt.
- Add a focusable leader overlay on `Space` from Machines, Images, and Inspectors. `t` opens another selected-user shell tab and `l` opens the native login attachment. Multiple tabs can target the same running container.
- Use `TERM=xterm-256color` for the embedded terminal and retain the native login path's root/elevated namespace fallback for containers without a system bus.
- Add `[settings] scrollback-lines`, defaulting to 2,000 history rows per terminal instead of 10,000. Release history after a session finishes while retaining its last screen and exit status.

## Runtime and provisioning fixes

- Rename `-c/--cli-mode` to `-s/--systemd-tools`. This selects the systemd execution path, independently of the TUI or command interface. Existing flags, the `cli-mode` setting, and `badge_cli` theme key remain accepted as aliases.
- Confirm systemd-tools starts using the nspawn unit's state instead of waiting for unit properties in a runtime-registration-only snapshot.
- Retain valid trailing-dot machine registrations in systemd-tools lists while keeping mutation validation separate.
- Remove the durable crash manifest when an unresolved deployment is explicitly released from its deployment view, so a successful release is not undone by the next startup. Host resources are left for inspection rather than automatically deleted.
- Improve deployment claim release, daemon job completion ordering, recovered-claim synchronization, stream write bounds, and subprocess cancellation/timeouts.
- Preserve administrator configuration and unrelated binds during NVIDIA updates, bound configuration reads, use unique atomic-write files, and pin daemon socket inodes before permission changes.
- Distinguish raw-image partition probe errors from images without a partition table, and clarify identity preservation during cloning and the trust required for guest post-configuration.
- Reduce Tokio, logging, dependency, and daemon memory overhead. Fix the aarch64 `fchmodat2` binding and remove deprecated musl `time_t` usage.

## Compatibility

Wayland binds are configured before container startup; Lasper does not create runtime binds or write persistent `.wayland-env` helpers. Existing compatible binds can be used without redeploying the container. Adding or changing a bind requires starting or restarting it.

This release continues to manage system-scope containers. OCI application-image support retains its existing experimental status.
