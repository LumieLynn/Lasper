# Lasper v0.3.0

Lasper 0.3.0 completes the 0.3 alpha cycle with a typed privilege boundary, explicit machine and image semantics, recoverable provisioning jobs, and a TUI organized around native `systemd-nspawn` resources. It remains an early-stage container manager, but this release establishes the architecture and operational contracts intended for subsequent 0.3 updates.

## Machine and image management

- Separate running machines from persistent images throughout discovery, inspection, selection, lifecycle actions, and terminal attachment.
- Preserve machined provider, class, state, and unavailable-property observations instead of coercing unknown or failed observations into nspawn defaults.
- Keep non-nspawn machined registrations visible for read-only inspection while withholding nspawn-only lifecycle, configuration, provisioning, and namespace actions.
- Track starting, stopping, and removing transitions so conflicting actions are rejected promptly without blocking unrelated resources.
- Remember machine and image inspector tabs independently and make panel tabs directly clickable.

## Elevated daemon and failure handling

- Run the recommended `lasper -e` mode through a per-session authenticated root daemon with private Unix sockets, exact peer PID/UID checks, bounded protocol frames, and typed RPC families.
- Use pidfds to pin daemon and terminal process identities, revalidate namespace terminal targets before attachment, and terminate tracked process groups when their session disappears.
- Bound short D-Bus, CLI, lock, and host-mutation waits while distinguishing not-attempted failures, semantic rejections, and operations whose final host outcome requires reconciliation.
- Preserve D-Bus and host inspection errors as typed application outcomes instead of classifying behavior from human-readable error text.
- Share direct system-bus connectivity without permanently caching an initial connection failure when the bus becomes available later.

## Provisioning

- Provide typed debootstrap, pacstrap, local artifact, remote Tar/Raw, clone, and experimental OCI provisioning paths across directory, Btrfs subvolume, and managed raw disk-image storage.
- Support cancellation confirmation, process-group termination, ownership-aware rollback, durable deployment manifests, and explicit recovery for outcomes that cannot be proven complete.
- Keep bootstrap provider defaults configurable, including package inheritance and provider-specific signature, repository, and host-integration policy.
- Persist the requested guest hostname inside the deployed root filesystem as well as the generated `.nspawn` configuration.
- Isolate custom image acquisition from materialization: remote sources use a bounded curl policy with implicit configuration disabled, while Tar content continues to target the storage backend selected by the user.

## OCI, terminals, and host integration

- Pull OCI application images through systemd 260 or newer `importctl pull-oci`, retain systemd's generated execution settings, and promote owned `.nspawn` configuration without overwriting administrator-managed files.
- Expose explicit Host, Isolated, and Veth networking for OCI applications and keep their `PrivateUsers=no` system-import policy visible as a security downgrade.
- Fall back from `machinectl login` to a fixed, typed `nsenter` shell for running nspawn containers without a system bus when Lasper has root authority.
- Generate NVIDIA CDI-derived device and library bindings with explicit device selection, and grant one or more discovered Wayland sockets to a selected container user.
- Accept both relative and absolute `WAYLAND_DISPLAY` values, including compositor-specific socket names, while revalidating ownership and socket identity before deployment.

## TUI and internal architecture

- Bound terminal, journal, deployment-log, and input queues; coalesce pointer motion and redraw work; restore terminal state on failures; and retain the relevant dekit terminal parser fixes.
- Keep modal focus, deployment cancellation, resource actions, terminal sessions, and asynchronous detail refreshes explicit in the UI state machine.
- Divide the backend into domain, application, IPC, adapter, composition, daemon, and TUI ownership layers, with boundary tests preventing transport and host authority from leaking inward.
- Replace the former shared nspawn model collection with validated domain values, application-owned service contracts, closed wire DTOs, and adapter-owned systemd projections.

## Compatibility and known limits

- OCI support remains experimental and is intended for application images; most OCI payloads are not bootable system containers without additional preparation.
- `lasper -e` requires Linux `pidfd_open` support and fails closed when the kernel does not provide it; `sudo lasper` remains the broader-trust compatibility mode.
- Remote Tar/Raw acquisition is Lasper-managed and does not use `importctl pull-tar`; the selected Lasper storage backend remains authoritative.
- GNU tar 1.35 or newer is recommended for untrusted archives. Older or unrecognized implementations require an explicit risk confirmation rather than being rejected outright.
- Review [CAVEATS.md](../CAVEATS.md) and [SECURITY.md](../SECURITY.md) before using the elevated daemon, namespace terminal fallback, private-user modes, or GPU and display passthrough on important hosts.
