# Lasper v0.3.0-alpha.1

This is a pre-release for testing the redesigned container lifecycle, terminal
experience, and privilege boundary before the 0.3 stable release.

## Highlights

- Reworked container creation, deployment, removal, and storage handling around
  explicit execution contexts and backend capabilities.
- Added a dedicated elevated daemon for privileged operations. Each interactive
  Lasper process launches an isolated daemon instance with a private Unix
  socket, peer credential checks, and a per-session authentication token.
- Added D-Bus-first systemd integration with command-line fallback where
  required.
- Improved the terminal UI with per-container logs, mouse selection, clipboard
  integration, new themes, and more consistent operation progress reporting.
- Expanded image and storage support, including OCI imports, raw images, ZFS,
  and NVIDIA CDI-aware container configuration.

## Security Changes

- The elevated daemon now binds its session to the exact launching user and
  process instead of accepting any process with the same UID.
- Daemon sockets are created in private, randomly named directories and are not
  exposed through predictable paths in `/tmp`.
- Privileged requests use structured messages and include a secret session
  token delivered outside the socket namespace.
- OCI image imports use a per-operation containers policy instead of modifying
  the host-wide `/etc/containers/policy.json`.
- Container configuration is retained when machine removal fails, avoiding a
  partially deleted state that cannot be retried safely.

## Compatibility And Upgrade Notes

- This release changes a broad part of Lasper's internal architecture and is
  intentionally marked alpha. Back up important container data before testing.
- Prefer running `lasper -e` as your normal user when privileged operations are
  needed. Running the complete TUI through `sudo lasper` expands the trusted
  code surface and is not recommended.
- Existing `0.2.x` configuration should be reviewed after upgrade, especially
  custom storage, networking, GPU, and bind-mount settings.
- The release workflow now publishes only from an explicit version tag. The tag
  must match `Cargo.toml`, and this manually maintained release note must exist
  before binaries can be published.

## Known Limitations

- The elevated daemon remains a high-privilege component. Authentication
  isolates independent Lasper sessions, but command/path authorization should
  continue to be narrowed before the stable 0.3 release.
- OCI imports currently permit unsigned images for the individual import
  operation. Lasper no longer weakens the host-wide containers policy.
- Two `quick-xml` RustSec advisories are temporarily excepted in CI. The crate
  is present only as a build-time dependency of the Wayland scanner and
  processes dependency-supplied protocol XML rather than runtime,
  attacker-controlled input. The exceptions should be removed as soon as the
  upstream Wayland dependency chain updates.
- RustSec also reports three allowed informational warnings in transitive
  dependencies. Their current exposure and remediation status are documented in
  `SECURITY.md`.
- Some imported root filesystems do not include a usable init system and may
  require manual preparation before they can be started with systemd-nspawn.
